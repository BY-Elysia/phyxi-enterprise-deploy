# P1a 独立 Nginx 运行边界

## 目标

先拆出业务网关的进程生命周期，为控制台重启后恢复网关状态建立基础。保持现有本地兼容路径，后续再切换内部网络和工作区鉴权。

## 变更

新增 gateway_container.rs，可选使用 Compose 管理的独立 Nginx，控制台不再持有其子进程句柄。检查角色标签、同路径状态挂载和实际运行状态后才执行 nginx -t/reload，不创建或删除外部容器。配置原子写入并 sync，实际生效的配置摘要经回环诊断接口核对，活动快照持久化；控制对象重建可恢复，不依赖旧 PID。无效配置恢复原文件，停用时确认 bootstrap 生效。增加本地过渡 Compose 覆盖、拒绝覆盖已有配置的初始化脚本及真实容器测试。

## 验证

- fmt、clippy -D warnings、cargo test（23 通过、1 个真实 Docker 测试默认忽略）、build、smoke-console.py、test-api-contract.py 全部通过。
- test-gateway-container.py 显式运行真实 Nginx 测试通过：TLS 匿名请求 401、控制对象重建后恢复、配置与快照匹配、无效配置不替换原服务、错误挂载拒绝、停止后业务网关未运行。只删除测试自己创建的唯一命名容器。
- 首次真实测试发现 Mac/Colima 文件挂载属性短暂延迟；增加唯一临时文件、fsync 和有界语法重试。另一次发现重载过渡期旧 worker 返回旧摘要；运行检查有界等待，不能确认时返回错误而不是误报停止。修复后完整检查及真实容器测试再次通过。

## 限制

P1a 仍使用 host 网络及旧共享网关令牌，不是最终企业安全部署。没有宣称控制台整个进程崩溃与流式请求连续性已完成联调（本次验证控制对象重建），也没有 GPU 推理证据。P1b/P2/P3/P4 仍待实现。诊断端口固定 18765，测试要求该端口无现有网关占用。旧原生进程模式继续供本地 CPU 测试使用。
