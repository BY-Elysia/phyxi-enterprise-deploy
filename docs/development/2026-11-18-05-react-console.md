# React 控制台与前端模块拆分

## 目标

把控制台按业务和职责拆开，控制浏览器首屏加载以及管理 API 的后台请求量。

## 变更

- React 渲染导航、资源卡片、模型广场、镜像目录和任务列表。模型筛选与分页、镜像版本选择由对应组件管理。
- `console/web/ui/core/` 提供同源 API 客户端、加载错误边界及轮询。业务模块独立管理配置编辑器、证书、日志、推理参数、生成预设和任务列表；`app.js` 连接路由、会话和模块。
- 模型广场、镜像目录、配置编辑器和监控视图按需加载。后台任务列表只在任务页、关联详情或主机操作中刷新，非部署页降低模型状态查询频率，后台标签页暂停轮询。相同的在途 GET 合并，日志归属校验单独读取。
- React 19.3.1 与 Scheduler 0.28.0 从锁定的 npm 发布包取得并校验 SHA-512。Rust 嵌入模块及 MIT 许可，React 资源提供预压缩和版本缓存。发布依旧使用 Cargo，浏览器通过同源地址获取资源。

## 验证

- 通过 Cargo 格式、Clippy、工作区测试、Debug 和 Release 构建、冒烟、API 契约及执行器测试。
- Chrome 回归覆盖模型、镜像、主机和逐卡监控、任务、日志、证书、推理参数、客户端生成预设及移动端。资源请求检查覆盖模型和镜像按需加载、部署列表暂停任务查询、并发 GET 合并、压缩协商及未知模块拒绝。

## 限制

配置表单、证书操作和监控图表内部沿用原生 DOM 逻辑，各自由独立模块维护。首次加载增加约 115 KiB 的 gzip React 运行时，后续访问可复用浏览器缓存。请求优化面向单机管理控制台，未做多实例调度或目标 GPU 压测。
