# 2026-11-12 · Ubuntu / A10 实机检查与修复

## 目标

将新版安装到用户授权的 Ubuntu / A10 服务器，验证实际环境与资源占用。依用户后续要求，停止耗时下载，完成其他检查后收尾，不宣称 GPU 推理已通过。

## 变更

- 增加受限的 `PHYXI_HF_ENDPOINT` 启动配置，支持官方 Hugging Face 与 hf-mirror；固定 revision、LFS 哈希校验保持不变，清单记录实际源。
- 将 Docker 环境探测输出缩减为版本和 runtime 名称。
- 修复真实任务错误信息撑宽列表的问题，长阶段文本截断为摘要，完整内容保留在任务日志。
- 添加有前置检查和清理步骤的 GPU 服务器验收脚本，留待镜像/权重完整后执行；本轮只做语法/帮助入口检查。
- 记录服务器安装、旧版归档、APT 源修复、CUDA 实测及未完成边界，不记录密码或令牌。

## 验证

- 本地 fmt、Clippy（warnings 为错误）、14 项 Rust 测试、构建、smoke 和协议测试通过。
- 服务器原生 release 构建、14 项 Rust 测试、smoke 与协议测试通过。
- 实际 systemd 非特权控制服务、受控环境准备、六项探测、自签证书生成/验证通过。
- A10 单 UUID CUDA 内核检查通过，退出后两张 GPU 显存均为 0 MiB；不等同于 vLLM 验收。
- SSH 隧道下检查实际服务页面，修复长日志布局；控制台单次采样 RSS 7508 KiB。
- 浏览器脚本和 Python 验收脚本语法检查通过。完整结果见 `docs/server-validation.md`。

## 限制

- 用户要求不再等待镜像下载：镜像和权重传输已停止，GPU/vLLM、网关模型转发及发布未实测，不存在后台自动验收。
- 已有 Docker/Toolkit 被复用，本轮未验证从零安装这两项依赖。企业 CA、Windows/OpenCode 与目标业务模型仍未验收。
- 镜像站元数据和部分文件可达，但服务器完整模型下载未完成；本地校验过的权重未完整传入服务器。
