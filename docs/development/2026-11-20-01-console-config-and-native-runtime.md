# 控制台配置与本机 vLLM 启动

## 目标

让管理员从服务器可见的文件系统选择权重，并让本机 vLLM 在缺少 Docker 和系统用户名的部署环境中使用指定的 NVIDIA GPU。

## 变更

- 权重选择器从根目录浏览。进入模型目录或选中 GGUF 文件后可直接提交。配置表单按用途组织常用字段和可选参数。
- 模型路径、参数方案和 GPU 分配分别校验。新增配置的权重路径留空，额外信任的模型根目录由管理员指定。备份工具读取执行器的安装配置。
- 将证书、网关和工作区接口拆为独立模块，共用命令执行、容器命令构造和部署实例归属检查。
- 本机 vLLM 子进程使用独立的工作目录及用户环境。启动时按 UUID 查询 GPU 序号并校验 PCI 排序，按选择顺序设置 CUDA 可见设备。健康检查直接请求本机模型接口。

## 验证

Rust 格式、Clippy、工作区测试和构建通过。控制台冒烟、API 契约、执行器和原生推理预设测试通过。验收环境通过控制台加载 Qwen3-Coder-Next 的全部 40 个权重分片，在两张 H20 上完成一次对话请求。

## 限制

本机 NVIDIA 模式要求所选卡的 PCI 排序与 NVML 序号一致。真实硬件验收覆盖上述双卡组合。曾依赖隐式信任模型目录的安装，升级时应显式配置对应的模型根目录。
