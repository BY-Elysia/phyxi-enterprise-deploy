# 发布包直达服务器与 Docker 导入身份兼容

## 目标

首个发布任务成功后，实机验证发现本机代理下载慢，以及目标 Docker 导入 OCI 索引后 ID 变化。补齐服务器直接下载路径与不可变配置摘要核验。

## 变更

- 新增 fetch-console-release.py：核对成功发布任务、完整提交 SHA 和未过期产物，本机通过 gh 获取临时下载地址；只传临时地址到 SSH stdin，不转发 GitHub 登录令牌。服务器直接下载、校验源码版本/架构/镜像 SHA256，原子保存，拒绝覆盖旧目录、路径越界和超限解压。
- 导入时优先复用已有 ID；若 Docker 重写索引 ID，通过实际 docker save 输出核对原始 config 内容摘要，再固定目标引擎的实际镜像 ID。拒绝只凭标签信任镜像；已验证镜像不重复导入。
- 将直达下载工具纳入发布包，并更新操作文档。

## 验证

- 首次 GitHub AMD64 发布任务 43579860184 成功，生成完整提交 SHA 对应离线包；Check 任务通过。
- 修正后的工具在服务器实测：直接下载及校验 13.07 秒；首次兼容性校验/导入 3.14 秒。服务器已有基础镜像层，数据不代表全新服务器冷导入耗时。
- scripts/test-console-release.py 六项测试通过，包括 OCI 索引变化、配置摘要不符拒绝、下载路径越界拒绝、架构/损坏包拒绝、安装不编译/不拉取和失败无残留。
- cargo fmt、clippy（-D warnings）、test、build、smoke-console.py、test-api-contract.py 通过。
- 没有重启现有服务器控制台、改变凭据或启动额外服务。推送后由工作流重新打包修正版，最终远端执行状态见 Actions。

## 限制

临时下载地址会过期，需重新运行获取；服务器不能直连产物存储时仍使用本机下载/传输。操作机需要 gh 登录及 SSH，目标机需要 Python3。首次镜像 config 摘要核验可能流式导出镜像，因此仍有磁盘/CPU 成本；不承诺固定时长。
