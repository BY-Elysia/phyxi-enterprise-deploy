# 待集中修复的问题

## 2026-11-14：企业接入组件位置与失败提示

状态：已修复。企业接入组件已迁移到企业网关，新增下载进度与中文失败说明；服务器隔离实例验证准备、停止/恢复、下载取消、失败和重试。详见 `docs/gateway-download-progress.md`。

### 原问题
- “企业接入组件”放在“服务器资源与依赖”页面，容易与宿主机环境安装混淆。
- Nginx 和工作区鉴权是企业接入服务，不属于宿主机软件依赖。
- “部署 / 恢复接入组件”没有清楚区分部署服务与开放业务入口，用户不容易理解用途和后续步骤。
- 用户截图中的部署失败发生在拉取 `docker.io/library/nginx:1.28-bookworm` 时：连接 Docker Hub registry 超时。界面直接展示较长的英文底层错误，未突出失败原因及下一步；不能误报为证书或模型配置问题。

### 已实施方向
- 将接入组件的状态、部署/恢复、停止及日志入口移到“企业网关”页面，作为启用企业接入的第一步。
- “服务器资源与依赖”保留宿主机资源、Docker、驱动、NVIDIA 容器支持及相应维护操作。
- 明确接入顺序：准备 Nginx 与工作区鉴权服务 → 配置网关证书和入口 → 配置工作区密钥 → 启用并验收。
- 用中文说明镜像下载超时与重试入口，原始错误收进诊断详情；镜像来源使用上一阶段已验证的显式配置，不静默切换来源。

### 验收要点
- 环境页不再出现企业接入组件部署区；网关页能查看、部署、停止并检查日志。
- 组件启动不自动开放业务入口，停止操作清楚说明对已有接入的影响。
- 下载失败时显示具体失败阶段，不误导用户修改证书或模型参数。
- 在服务器验证，按项目规则附开发纪要、测试通过后提交并推送 dev。
