# PhyXi 控制台界面规范

## 目标与边界

面向少数运维人员管理单服务器、单运行模型。界面优先回答：当前对象是什么、状态如何、下一步能做什么、操作影响什么。保持 Rust 内嵌静态 HTML/CSS 和原生 JavaScript，不引入组件框架、外部字体、图标 CDN 或前端构建服务。

参考 [Ant Design 数据展示规范](https://ant.design/docs/spec/data-display/) 的信息层次、表格与空状态，以及 [Carbon 通知规范](https://www.carbondesignsystem.com/building-blocks/core/patterns/notifications) 的上下文反馈原则；借鉴成熟企业控制台的组织方式，不安装这些 UI 框架。

## 信息结构

| 导航分组 | 页面 | 展示职责 |
|---|---|---|
| 模型服务 | 部署实例 | 列表进入独立详情，组合配置、查看状态、执行部署 |
| 资源与配置 | 模型权重、推理引擎镜像、推理参数 | 分别保存下载来源、Docker 镜像地址、推理选项 |
| 企业接入 | 企业网关、客户端工作区 | HTTPS 与来源限制、客户端身份及独立密钥 |
| 运维与审计 | 服务器资源与依赖、操作记录、验收与发布 | 资源检测、任务与审计、真实验收与发布历史 |

导航统一使用轻量线性图标、分组标题和选中态；顶部显示当前位置、真实模型状态和管理员。登录使用独立页面，不嵌在控制台内容中。

## 页面与组件

- 列表统一提供名称、配置摘要、修订号、查看/编辑、数量、当前列表搜索和明确的新建入口。空列表提示如何创建，搜索无结果提示修改关键词。
- 部署详情使用独立路由。状态卡片与分组参数表呈现业务信息，不直接展示组合配置 JSON。诊断详情与日志按需展开。
- 编辑使用右侧抽屉，按服务标识、下载来源、资源分配、访问规则等业务职责分组。预设选择与手工配置保留各自含义；“保存配置”明确不会启动服务。
- 抽屉保存/取消在右侧，删除在左侧；证书上传与密钥展示使用居中紧凑弹窗。危险操作沿用自定义确认弹窗，列明对象与影响。
- 主操作使用强调色；次要操作使用中性描边；危险操作使用克制的红色。无所属实例时禁用停止、重部署、验收和实例日志，附原因。
- 操作记录分为任务列表与详情，展示对象、状态、时间、步骤和实际日志；配置快照折叠呈现。管理员审计使用表格。
- 验收页用结果徽标、验收项表格和发布详情展示真实记录；不把整个响应 JSON 当成页面。

## 反馈约定

1. 操作触发后必须显示正在执行/检查状态，并防止重复触发。
2. 配置组合检查在按钮附近显示明确结果，不依赖用户猜测页面哪里变了；不冒充运行前健康检查。
3. 错误可关闭，切换页面清理无关提示；无实例是正常空状态，不能因后台轮询持续刷错误。
4. 网络失败给出失败原因和可重试入口，不能把失败伪装成无记录。
5. 未检测到的指标不填造假数值；运行状态、配置草稿和操作任务是不同概念。

## 视觉与可访问性

统一浅色背景、白色内容面板、细边框和蓝色强调；主标题、段落、标签、帮助文字使用稳定层级。表格保证名称和动作可辨认，长路径允许换行或在表格容器横向滚动。日志采用浅色等宽区域。

支持键盘焦点、表单标签、状态播报、跳到正文、减少动画偏好。窄屏将卡片/参数变成单列、导航变成横向滚动、表单保持可用。按钮禁用不只依赖颜色，危险操作也必须有文字说明。

## 回归检查

每次修改共享样式或交互后，检查独立登录、全部导航入口、列表/搜索/空状态、详情、六类配置表单、任务详情、服务器检测与验收记录。核对浏览器脚本错误，保留必要截图。执行仓库规定的 Rust、冒烟和 API 契约检查。

浏览器测试使用隔离数据目录；不得为了 UI 测试停止外部服务、下载大型模型、撤销真实工作区密钥或改动已有部署。视觉检查不等于真实 GPU 推理、企业 TLS 或跨浏览器兼容性认证。
